# 04 — الملاحة والتحكم + الاتصالات والمرونة (مطلب 6، 7، 13 جزئياً)

## 1. الملاحة والتحكم

### 1.1 الطبقات (من الأدنى إلى الأعلى)

```
  PID + تحكم torque (المحركات)  ─►  fusion INS/GNSS/VIO/Terrain  ─►  مخطط محلّي
        (زمن حقيقي 100–400Hz)          (10–50Hz)                       (تعقّب مسار + إعادة تخطيط)
                                            │
                          مخطط المهمة المسبق + توأم رقمي + خريطة خطر ديناميكية
                                            │
                                     تأكيد بشري + سجل
```

- زمن حقيقي صلب على فئة NuttX/ArduPilot-fashion للمنافذ البينية، مع مُخطط مركّب على ROS 2 للمرافق. ✅
- تجنب العوائق: طبقات — تخطيط هندسي (A*/RRT* على خريطة مخزنة 3D) + رد فعل سريع (LiDAR+Optical Flow) — المنطق موجود في محاكياتنا المعايرة الحالية.
- GNSS-denied: أولوية — VIO حراري وبصري + odometry LiDAR + مطابقة تضاريس؛ ثم تعديل مسار اقتصادي (لوزن الأطوال الزمنية). 🟡 (أقصى دقة عند طول فترة العمل المبدأ)
- عودة تلقائية (RTL) عند انقطاع الاتصال (> مهلة مُعرَّفة): مسار مخزن محكوم بـ *مسار بر، نطاق ارتفاع محفوظ، ومسح راداري للعوائق*؛ تعالج عند انقطاع.
- هبوط اضطراري مدروس: محدد موقع هبوط آمن قائم على الفائدة (flatness + عدم وجوم أشخاص + راحة سطح) — شجرة قرار مُفصَّلة بأولويات صارمة.
- Geofencing: كل أمر طيران جديد يمر عبر فلتر منطقة حظر ثلاثي الأبعاد (مناطق مطارات، تجمّعيات حساسة، عرضيات) مصبوب بـ YAML موقّع.

## 2. الاتصالات والمرونة (مطلب 7)

### 2.1 الروابط المطلوبة

| الرابط | الغرض | النطاق | تقدير المعدل | الرباعية |
|---|---|---|---|---|
| نطاق متقارب C2+فيديو | قيادة ورؤية أساسية | 900 MHz / 2.4 GHz FHSS أو COFDM مُنقى | 1–10 Mbps @ 5–15 كم | ✅ |
| رابط Mesh بين السرب | تبادل الخرائط والأهداف لحظياً | 2.4 GHz (الهدف 3 hops) | 0.5–2 Mbps per link | 🟡 |
| backhaul LTE/5G حيث متوفرة | تسريع تحميل ضخم إلى الأرض | شبكة مدنية مزودة | يعتمد | ✅ |
| قمر صناعي (أقل معدل ممكن) | أمر طوارئ + موقع (أثر) | SBD-فئة | بضع كيلوبتات حرجة | ✅ |

### 2.2 ضد التشويش والانقطاع (دفاعي صِرف)
- قفز ترددي وطيف منتشر + AMC تكيّفي (معدل/ترميز يتبع حالة الرابط الفعلية).
- هوائي توجيهي قابل للتوجيه إلكترونياً أو ميكانيكياً ضعيف (عدد درجات صغيرة) يقلل تعرض NLOS.
- **كشف تشويش خفيف** من نمط الخسارة و SNR و RSRP خصائص — المنطق نفسه مرصود في مبادئ كشف الاستشعار في مشروعنا الحالي (مصلحة وقائية فقط).
- مسارات بديلة:<br>فقدان LTE → Mesh أخوي → C2 الأساسي → هاب RTL بحيث منطقة منكوبة تبقى بخدمة الجسد المادية (محطة إعادةإرسال).
- تسجيل كامل للرحلة/الحمولة مشفر ومضغط زمنياً (أثر تدقيق أولي).

### 2.3 الأمن السيبراني (نطاق الدفاع فقط)
- مصادقة متبادلة PKI لكل طائرة (شهادات قصيرة)، أوامر موقّعة مضادةللإعادة (Nonce + Monotonic count)، خوارزميات سمة متوارثة حديثة (Ed25519/AES-GCM-فئة).
- عزل النواة: حارس السلامة مستقل عن السحابة؛ جدار تطبيق لشبكات Mesh (لا ثقة ضمنية بجهاز مرسل ضمن الشبكة).
- حماية OTA: إمضاءات مزدوجة + قطاع rollback — لا تحديث في أثناء الطيران.

## 3. شبكة اتصال طارئة (مطلب 13)

```
  طائرات سرب فوق المنطقة المنكوبة
     │ Mesh (2.4 GHz, عدة hops)
     ▼
  طائرة "جسر أعلى" (الكبرى) ── LTE/قمر صناعي ──▶ غرفة الطوارئ/محطة أرضية
     │
     ▼ بث محلي قانوني:
     - WiFi AP مؤقت SSID معروف لدى غرفة الطوارئ
     - ترحيل نداءات RF (بما يسمح التنظيم)
     - بث تنبيهات مدنية مفصولة تماماً عن أوامر القيادة نفسها
```

- الطائرة الكبرى تصبح **برجاً مؤقتاً** (خدمة مدنية فقط)، مع فصل صارم بين Service شبكة الضحايا وبين قنوات السيطرة C2 (VLAN+توقيع/OTP).
- "إعادة بث إشارة الاستغاثة":ت بتنسيق مع المشغل بعد إعلان الرخصة المحلية، كلمة سريعة من ميزانية الصدق.
