# 07 — السلامة والأخلاقيات + واجهة المشغل + البرمجيات (مطلب 15، 11، 16)

## 1. إطار السلامة والأخلاقيات (مطلب 15)

| المبدأ | الآلية |
|---|---|
| لا أسلحة/متفجرات/هجوم | قائمة حمولات **علنية** + سجل تدقيق + فصل صارم عن أي Assumption مهاجم |
| احترام الخصوصية | تمويه وجوه/لوحات على متن الطائرة فوراً، لا بث خام لعامة الناس، حاجب بيانات حكم محكوم |
| موافقة بشرية عند الحاجة | إسقاط طبي/فوق تجمع → تأكيد مشغل إلزامي (ملف 05) |
| الامتثال القانوني والإنساني | مراجعة قانونية محلية لكل منطقة، تنسيق غرفة طوارئ رسمية |
| حماية البيانات | تشفير وتوقيع، تخزين موجز على AMP قصير، أرشفة طارئة عند العودة فقط |
| شفافية القرار | XAI + سجل سببية (لماذا تم اتخاذ قرار)؛ تقارير قابلة للتقصي |
| تقارير فورية للجهات | Panel موحد + تقرير مهمة PDF سجلسته الأصول المنهجية |
| مراقبة الجودة الأخلاقية | مراجعة أخلاقية على كل إصدار swift (لجنة محايدة، شركاء إغاثة) |

> ملاحظة صدق محكومة: لا نقدر قابض نظام GDPR إلا بعد طرق مسح قانوني للبلدان الناشرة، ونص التحديد يبقى مسودة drafted by التنسيق المحلي.

## 2. واجهة المشغل البشري (مطلب 11)

- **لوحة مراقبة التحكم (GCS)**: خريطة مباشرة، مؤشر ثقة لكل هدف، أزرار "تأكيد/إلغاء" بارزة، HUD ترددي وقت حقيقي.
- **الإغلاق اليدوي**: زر عودة فوري واحد، زر هبوط اضطراري واحد، زر محو حمولة بإتقان بقعاني (تُزيح الكاسيت نقطة سقط آمنة).
- **تسجيل قرارات مع سببها**: يجب تقديم وسيلة لتعقب "لماذا" (XAI مُسبب من ملف 03)، مقترنة بالنتيجة المرئية لكل طاقم متاح.
- **إشارات حسية**: المنبهات ليست فقط نصية — alert صوتي خفيف ونافر بصري بسيطا كي لا يفوت الإنذار وقت الانشغال.
- إمكانية التدخل في أي لحظة، حتى لو القيد الحديدي يعمل باستقلال: stack القيادة اليدوية هو النهاية في ترتيب الاستثناءات.

## 4. أرشيف البرمجيات الداعمة للتنفيذ والاختبار (هيكل المستودع المقترح)
```
/repo_root
  ├ entries/flight-stack (PX4-class الحقيقيات)
  ├ entries/companion-containers (ubuntu-noble,Ros)
  ├ airlab/               (بنياتنا المحاكية الحالية — أقوال على الرؤية)
  │   ├ guardian/          (حارس: thermal/replan/perception/edge_split)
  │   └ tools/             (thermal/fly demos)
  ├ sim/                   (Gazebo worlds + عدنان يعمل + seed spans)
  └ docs/rescue-drone/      (هذه الوثيقة)
```

## 5. مسار التحقق البرمجي (flow من Git)
1. كل ميزات الأساسيات تجحّت برامجاوية في محاكاة + اختبارات موحد.
2. مراجعة بشرية متقاطعة للأكواد الحرجة في مسار الطيران (flight-critical).
3. HIL (اعتبار flight stack في الدائرة) قبل أول طيران حر.
4. إطلاق الإصدار الأول رَفقة قناة الرحلة (flight channel)، ثم ترقيات عبر OTA موقّع.

## 6. قرارات حرجة تبقى مفتوحة للنقاش في البرنامج
- الحد المقبول للتصنيف الطبي الآلي بالكاميرا: يبقى مؤشراً أولياً يؤكده فريق طبي بشري، ولا يُتخذ عليه قرار معالجة وحده.
- مستوى عزل النواة الأمنية المقبول بالتوازي مع حماية البيانات من دون سحابة.
